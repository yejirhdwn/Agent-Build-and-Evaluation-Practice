# 발송·결과 흐름 참고

## 발송 흐름

일반적인 발송 흐름은 대상 추출, 오퍼 할당, 메시지 생성, 채널 발송 순서다. 각 단계의 입력·출력과 선후행을 배치 목록 조회로 확인한다. 캠페인 단위 트랜잭션을 사용하는 마지막 발송 단계는 커밋 전 검증 실패 시 전체 작업이 롤백될 수 있으므로, 커밋·롤백 로그와 실제 이력을 함께 비교한다.

## 결과 흐름

결과 수신 단계가 발송 이력과 반응 결과를 적재하고, 성과 집계 단계가 그 테이블을 읽어 화면용 집계 테이블을 만든다. 화면 값이 이상하면 화면의 DAO가 읽는 테이블부터 시작해 쓰는 배치와 원천 테이블을 확인한다.

## 확인 항목

- 배치 스케줄과 선후행
- 입력·출력 테이블
- 화면과 테이블의 관계
- 상태 전이와 건수
- 캠페인 발송일과 실제 처리일
- 결과 수신 테이블과 집계 SQL의 원천 테이블 일치 여부
- 각 테이블의 마지막 적재 시각
